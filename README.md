# 最強の名前トーナメント 管理ツール(仮称)

v0.3.0。回答収集・Discord整形・トーナメント進行を行う、ビルド不要のブラウザツールです。サーバー、APIキー、外部ライブラリは不要です。

## 既存サイトの更新

1. 現在のツールで「全大会をバックアップ」を押し、JSONを保存します。
2. ZIPを展開します。
3. **展開したフォルダの中身をすべて、既存のGitHubリポジトリの同じ場所へアップロード**します。フォルダごと下の階層に追加せず、既存の `index.html` と同じ階層に置いてください。
4. Commit changes後、Pagesの公開処理が終わったらサイトを再読み込みします。ページ下部に **v0.3.0** と表示されます。

今回は新しいJavaScriptファイルが3つあります。以前の「2ファイルだけ上書き」では動きません。動作に必要なファイルは次の7つです。

- index.html
- style.css
- core.js
- app.js
- bracket.js（追加）
- bracket-image.js（追加）
- tournament-ui.js（追加）

同じサイトURL・同じブラウザで更新すれば、以前の回答と大会設定を引き継ぎます。古いバックアップにも対応します。新しいバックアップにはトーナメントの参加回答・抽選順・勝敗も含まれます。

## 初めての起動

PCではZIPを展開し `index.html` をブラウザで開きます。iPhoneはGitHub Pagesでの利用を推奨します。GitHubのリポジトリに展開した中身を置き、Settings → Pagesでブランチのルートを公開します。発行されたURLを開いて操作してください。

PythonがあるPCでは、このフォルダで `python3 -m http.server 8000` を実行し、`http://localhost:8000` でも開けます。

ソースには実回答を含めていません。実回答CSVやバックアップJSONを公開リポジトリに置かないでください。

## トーナメントを試す

1. 「トーナメント管理」タブを開きます。
2. 入力元を **仮データで試す** にします。
3. 件数を2〜256で指定します（初期値16）。
4. 2〜10人戦それぞれの構成案が表示されます。「この構成」で選びます。
5. 必要ならランダム並び替えをオンにし、「トーナメントを作成」を押します。
6. 対戦カードで勝ち上がる名前をタップします。次の対戦に自動で入ります。
7. ラウンドタブで決勝まで進めると優勝回答が表示されます。

仮データはトーナメントだけに使います。収集した実回答を置き換えません。同じ大会にすでにトーナメントがある場合、作成し直すと組み合わせと勝敗を置き換えます。

### 参加回答の入力

- **収集した採用回答**：回答収集側で採用になった行を使用します。参加する行をチェックで絞れます。256件を超える場合、無断で切り捨てず、選択を減らすまで作成を止めます。「上から256件を選択」も使えます。
- **名前を直接入力**：改行ごとに1回答、最大256件。空行は無視します。同名の行も別回答です。
- **仮データで試す**：2〜256件の架空回答を生成します。

**同じ投稿者でも、スプレッドシートの1行が1つの参加枠です。** 同じ名前の回答も別IDで管理します。名前と「必殺技など」の項目は対戦カードの「回答詳細」から確認できます。

### 構成案の「最適」について

1試合から1回答が勝ち上がる、敗者復活なしのシングルエリミネーションです。1戦の設定人数は**最大人数**です。端数がある場合、初戦に2人以上・設定人数以下の少人数戦を置き、残りを初戦シードにします。シードは1人だけの架空試合として勝敗入力させず、自動で次のラウンドへ配置します。

参加数N、1戦の最大人数Kに対し、次の優先順位で構成します。

1. 最短ラウンド数（Kの何乗でN以上になるか）
2. 最少試合数 `ceil((N - 1) / (K - 1))`
3. 初戦の対戦とシードを上位の山に分散

例えば17回答・最大3人戦なら、初戦は3人戦4試合＋シード5回答、その次は3人戦3試合、最後は3人戦1試合です。合計8試合・3ラウンドになります。

シードを完全に無くす方針や、全試合を必ず同人数にする方針ではありません。実力順シードや同一投稿者の対戦回避はありません。ランダム並び替えをオンにすると、シードを含む位置も抽選になります。

### 勝敗の指定・訂正

- 出場する全回答が決まった対戦だけ、勝者を選べます。
- 勝者を選ぶと上位対戦へ自動反映し、回答名の手動コピーは不要です。
- 勝者を変更・取消すると、影響する上位対戦の結果を解除します。別の山の結果は保持します。
- 「勝敗だけリセット」は組み合わせを維持します。
- 「再抽選する」は同じ参加回答を再シャッフルし、すべての勝敗をリセットします。
- 回答の収集元を更新しても、進行中のトーナメントは作成時の回答を保持します。変更は表示で知らせます。最新回答を反映するには、確認のうえトーナメントを作成し直してください。

### トーナメント画像

全体図は対戦枠と接続線を持つ図です。「トーナメント全体図を見る」から画面でも確認できます。

「画像で共有」で情報と範囲を選んで「画像を生成」を押します。生成後に「PNGを保存」、対応するブラウザでは「共有する」が使えます。

| 情報 | 回答名 | 勝敗・優勝 |
| --- | --- | --- |
| 現在の進行状況 | 表示 | 表示 |
| 事前公開：勝敗を隠す | 初期の組み合わせを表示 | 非表示 |
| 事前公開：回答名と勝敗を隠す | 回答001などの番号だけ | 非表示 |

- PNGには投稿者IDと回答詳細を含めません。長い回答名は画像上だけ省略します。
- 全体図は端末で扱える大きさに縮小します。256件など大きい表は文字が小さくなるため、**表示中ラウンドの画像**も使ってください。こちらは8試合ずつに分割し、勝者の進む対戦IDを表示します。各ページを個別に保存できます。
- 「Discord用スポイラー画像」にすると `SPOILER_` 付きファイル名で保存します。Discordの添付プレビューでも「スポイラーとしてマーク」を確認してください。写真アプリなどを経由するとファイル名が変わる場合があります。
- スポイラー指定は画像そのものを暗号化しません。中身を絶対に出したくない事前公開には「回答名と勝敗を隠す」を併用してください。
- Discordへの自動投稿は行いません。参照：[Discordのスポイラー設定](https://support.discord.com/hc/en-us/articles/360022320632-Spoiler-Tags)

## 回答収集・Discord整形

1. 大会を作成して回答上限を設定します（初期値3、0は無制限）。
2. Google Sheets URLまたはCSVを読み込みます。
3. Discord IDと名前の対応列、「必殺技など」（0〜5項目）を選びます。
4. 採用・上限超過・未入力を確認します。
5. 見出し、項目名、連番、コードブロックを設定して出力をコピーします。

### シート読込

初期列は「タイムスタンプ / discord ID / 新商品の名前 / 新商品のジャンル / 新商品の説明」です。別の表は列を選び直せます。

URL読込は、GoogleからログインなしでCSV取得できる表向けです。gid欄を指定するとURLのgidより優先します。両方未指定なら0です。アクセス権やCORSにより失敗する場合があります。Googleログイン機能はありません。

非公開シートはGoogle Sheetsで対象タブを開き、**ファイル → ダウンロード → カンマ区切り形式 (.csv)** で取得して読み込んでください。表を公開する必要はありません。CSVはUTF-8・先頭行が列名・1行が1回答です。引用符で囲まれたセル内改行やカンマにも対応します。

読込は毎回、回答一覧を表の内容で置き換えます。同じ表の再読込で二重計上しません。手動更新です。Google Formsへの書込みやバックグラウンド取得はありません。参考：[Googleのシート接続仕様](https://developers.google.com/chart/interactive/docs/spreadsheets)

### 回答上限と出力

- 大会ごと・Discord IDごとに、表の上から順に数えます。タイムスタンプでの自動並べ替えはありません。
- IDの前後空白、先頭@、英字の大小を統一します。数字IDと `<@数字>` も同一視します。数値IDは文字列として保持します。ユーザー名と数値IDは別の値なので、フォームの入力形式を統一してください。
- IDまたは名前が空欄の行は採用せず、上限枠も使いません。上限超過の行は一覧に残します。上限変更で再判定します。同名回答の自動削除はありません。
- Google Formsの送信を制限する機能や、本人確認機能はありません。
- 「必殺技など」は選んだ順、「その他の出力項目」は表の列順に名前の後へ出力します。同じ列は二重出力しません。
- コードブロックは1回答ずつ囲みます。**同じ投稿者でもコピー欄は回答ごとに独立**します。1回答が1,900文字を超える場合だけ、さらに分割します。
- `{大会名}` は見出しで使用できます。メンションと入力内のコードフェンスは無害化します。Bot・Webhookによる送信はありません。

## 保存・バックアップ

大会・回答・トーナメントは、同じブラウザと同じURLのlocalStorageに自動保存します。端末間同期、共同編集、管理者認証はありません。ブラウザデータの削除などで失われるため、バックアップを保存してください。ローカルファイルを開く場合の保存挙動はブラウザに依存します。

「全大会をバックアップ」でJSONを書き出し、「バックアップを復元」で全大会を置き換えます。復元前には確認が出ます。ブラウザへの保存に失敗した場合も画面上のデータは保持して通知します。バックアップには実回答・ID・勝敗が含まれます。

## 開発・検証

Node.js 20以降で `npm test`（npm install不要）。

- core.js：CSV、ID集計、Discord整形
- app.js：大会・収集・保存・バックアップ
- bracket.js：構成生成、シャッフル、勝ち上がり、結果の整合性検証
- bracket-image.js：SVGの配置と生成、PNGへの変換
- tournament-ui.js：参加設定、対戦カード、画像保存・共有
- tests/core.test.cjs：既存の収集・整形テスト
- tests/bracket.test.cjs：全2,295構成、勝者変更、バックアップ、画像の伏せ字・配置テスト
- tests/ui.test.cjs：軽量DOMによる入力・勝者指定・保存・大会切替の統合テスト

計22テストが通過。2〜256回答と2〜10人戦のすべての組み合わせで、重複・欠落、最短ラウンド、最少試合数を確認しています。

軽量DOMのテストは実ブラウザの描画試験ではありません。検証環境からローカルサイトへ接続できなかったため、実ブラウザでの表示・PNG生成・iPhoneの保存／共有の一連の操作は未確認です。SVGは静的な配置検査を実施しています。
